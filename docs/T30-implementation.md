# T30 media downloads — implementation

The existing fresh-authenticated, CSRF-protected POST /account/export retains its JSON default. Selecting include_uploads=yes returns an immediate private ZIP containing the same account JSON, generated-name media files, a SHA-256 manifest and README. This initial bounded synchronous implementation supersedes the earlier background-job/24-hour-file proposal: it retains no ZIP on disk and creates no bearer download URL. Four attempts per account/hour and the shared upload lock bound repeated/concurrent generation. Source files are limited to 64 MiB, archive output to 72 MiB and candidates to 2,000; it never raises upload allowances or consumes temporary disk for the archive.

Authoritative owner entries in the shared upload ledger select attachment/artwork files for the current environment/account only. Personally submitted consent-document originals are included from their parent attribution. Unknown legacy uploaders require support review; no current Page/Circle owner inference is used. Missing/unsafe files are explained generically in the manifest without exposing storage paths. Retained upload derivatives are included where separately attributed; unavailable/deleted originals and remote embeds cannot be recreated. Private staff additions and other people's uploads are excluded.

Every path component is opened with no-follow dirfds, regular files only. Device/inode deduplication prevents hardlink duplication. Generated archive names avoid user-controlled ZIP paths. Size, metadata and hash checks guard changed files; over-limit/changed exports fail rather than claim completion. Responses are private/no-store, download-only, nosniff and sandboxed. Deployment must not generate or download real account exports for testing.

Tests: 15 archive checks, 29 full-application acceptance checks per environment, existing resource-recovery regressions, plus 38 provider-independent marketplace money/shipping checks. Full-app fixtures copy databases privately, use fictional identities and isolate the upload ledger, uploads and private documents; SMTP is disabled. No new schema migration is needed.

T31's marketplace_core.py is a tested foundation, not an enabled marketplace: integer-cent fee quotations, cumulative proportional commission credits, selected seller/paid physical-order shipping CSV and dry-run tracking validation. Pirate Ship export uses stable order/parcel references, UTF-8, original text postal codes and explicit package measurements. It refuses formula/control cells and cross-seller or inappropriate order state. Tracking previews preserve text identifiers, reject conflicting duplicates and never write payment/delivery states. A future seller UI must map provider headings, recheck authoritative rows transactionally, preview/confirm updates, and complete a real Pirate Ship spreadsheet round trip before activation. No Shippo/Stripe/PayPal/Google Pay network integration or live commerce is implied by these helpers.
