# Marketplace listing browser and owner-authorized preview imports

Marketplace opens directly to a read-only listing browser, not seller setup. Search matches public title, description or shop name, with literal wildcard escaping and bounded input. Sort choices are newest (default), oldest, price ascending/descending and best selling. There are no accepted Neonrest sales yet: best selling explicitly falls back to newest, never counts unpaid test orders and shows no invented sales badges. Real sales ranking must be derived from the future accepted-payment/refund ledger. URL parameters retain search/sort during pagination; pages contain at most 24 candidate records plus one lookahead, with bounded page numbers and no disclosure of hidden records or totals.

Create a listing opens the listing form directly. The default is the seller's personal @profile; an owned creative _Page or business $Page is optional. A corresponding private shop is reused or created transactionally, without creating a Page or buying a subscription. Invalid forms roll back that shop creation. Normal adult eligibility, account restrictions, fresh authentication, CSRF, throttles, Page ownership and revision checks remain enforced. Listings use the selected shop's identity/team permissions, not a new per-item role system. Each seller still needs a basic personal Neonrest profile.

`marketplace_publications` is an explicit trusted preview grant. There is no seller-facing publication action. The grant identifies a listing's reviewed revision and up to five individually approved product-image IDs. Unreviewed drafts never appear. Changing the draft revision, archiving it, withdrawing the grant, losing seller eligibility, blocking/muting, age restrictions, or an unavailable/transferred linked Page removes access. No PDF/ZIP/TXT product file is publicly served. The public image route rechecks the grant, active image association, actual uploader eligibility, no-follow file path and recorded size/hash, then returns only processed WebP with private/no-store/nosniff headers. Future public selling needs its own publishing and delivery review; a preview grant is not purchase availability.

The owner explicitly authorized copies of OregonButtonStore public Etsy listings, photos and copy to prepopulate the browser. Only selected public product content is imported, with source URLs. No reviews, customer data, Etsy sales totals, credentials or account details are imported. Preview prices are captured examples; no stock/shipping estimate or completed payment is implied. No separate @OregonButtonStore account is invented: the shop belongs to the existing actual owner profile. A separate account must use normal account/age/credential setup.

`marketplace_shop_benefits` records a trusted owner-specific complimentary platform-fee policy. It is bound to both shop and current owner; ordinary seller forms cannot grant it. Both the initial listing fee and Neonrest sales commission are waived for the designated owner shop; future listing billing must consult this policy before charging. Test quotes already snapshot a zero platform fee for that owner benefit, without changing other shops' 6% quotes. Third-party processing costs are not waived. The record is included in the owner's private export. No real fees are currently charged anywhere.

The two new tables are additive and initially empty. Restore and repeat initialization must preserve every existing table value and foreign-key integrity. User-authorized catalog seeding is a separate audited operation after code deployment, with a fresh pre-seed database backup and exact source/listing/image hashes retained privately. Uploaded photos use the existing owner/shared quota ledger; account export attribution remains with the actual owner uploader. Publication grants and comp records are retained for accountability; permanent erasure remains disabled.
