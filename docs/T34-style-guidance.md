# Style and graphic-element guidance

Sandbox editor presentation change; no schema or stored-content changes.

Style & graphic elements now pairs its controls with a native-renderer example for Classic, Punk or the current live composition. Empty preset fields use clearly labeled example copy. Style, accent, section, banner/quote and highlight inputs update the example without submitting or rewriting the page. Composition previews clone the live canvas without selection handles. An Enlarge example toggle is presentation-only.

Explanations distinguish Classic's ordinary text/artwork layout, Punk's graphic panels and cover treatments, and composition's separately edited canvas. Controls unused by the selected style/page kind are visually indicated and explained, while remaining editable for preparing a different preset. Front cover, interior and back-cover contexts come from the actual page kind. Previewing does not change composition data. Final reader/PDF review remains necessary.

Validation: 54 existing component checks, three native template page contexts and fifteen actual DOM-event checks for style/accent/highlight updates, literal-text safety, inactive controls, cover/back behavior, canvas preservation, enlargement and no submission. Hosted application acceptance is a separate deployment gate. Live connected-browser visual acceptance remains subject to the session's browser availability.
