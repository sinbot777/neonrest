# Independent Marketplace and shop identities

Marketplace has its own public `/marketplace` destination and shared navigation entry. Seller Studio and shop creation are reached directly from Marketplace. Public listings and purchases remain disabled; the landing screen describes preparation honestly rather than displaying private drafts.

Eligible adults can create a shop without creating any Page. A shop has a stable opaque key and personal-account owner. Its optional identity link is the owner's current personal @handle, an owned creative _handle Page, an owned business $handle Page, or none. Business subscription entitlement is independent of Marketplace access. Current owned unarchived/unhidden Pages may be linked from Seller Studio; foreign/delegated-only Pages cannot be claimed.

An identity link never transfers ownership, listings, files, uploader attribution, test-order snapshots or quotas. Linking a Page grants its current eligible adult editor/manager team listing access under the existing block, age, restriction and revocation rules. Removing/changing that link immediately removes prior team access. Personal/unlinked shops have no implicit delegates. Shop policy and identity changes remain owner-only, fresh-authenticated, CSRF-protected, throttled and revision checked.

An archived linked Page remains read-only. A transferred or hidden linked Page freezes normal shop access; the actual shop owner can recover via Marketplace → Seller Studio → Manage identity link and detach or select another owned identity. The new Page owner never acquires the old shop. Ordinary linked-Page restrictions and owner eligibility are rechecked on each listing/file/checkout request. Any future commerce moderation hold must be independent of Page identity, so unlinking cannot lift a shop-specific hold; no such public commerce state is enabled here.

The legacy `seller_shops.page_id` column now stores the stable shop key for compatibility with all listing, media, quote, order and audit references. It is no longer a mandatory foreign key to identity_pages. Existing shop keys and all previous column values are preserved by a transactional create/copy/drop/rename migration, with original Page association stored explicitly as `identity_kind='page', linked_page_id=<old key>`. All child foreign keys retain their existing target. Run on a dedicated idle connection, preserve the connection's foreign-key setting, validate foreign keys before commit, and rehearse a populated migration and rollback before deployment. No invented Pages or account identities are created. Legacy `/marketplace/studio/<old-page-id>` links continue working.

Owner account exports now include the actual owner's standalone and linked shops. Identity transfers do not grant the new Page owner another seller's exports. Existing product-file exports continue following actual uploader attribution.

This stage does not implement provider onboarding, real checkout, public storefront/backlinks, shipping/tax, payouts, labels or commissions/memberships. Payment integration follows this identity change. Public Page/profile storefront links require public commerce eligibility and publication checks in that later stage; private shop URLs are not exposed on public identity pages.
