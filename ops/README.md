# Managed mail workers

The managed supervisor runs independent Sandbox and Production child processes in the existing PythonAnywhere always-on task slot. Each worker retains its own database, private encryption key/epoch, replay ledger and exclusive worker lock. A child failure restarts only that child after a delay. Removing the Production gate stops only Production; shutdown reaps all owned children. A private, atomic supervisor heartbeat is written next to its configuration for verification across hosting execution surfaces.

Copy the example configuration to a private directory (0700); set the configuration file to 0600. Review the paths against the actual deployment. Provision Production separately with its mail_queue.py --provision while its web queue is disabled and any existing jobs have been reviewed. Never copy Sandbox jobs, keys, epochs or ledgers into Production. The repository example contains no key material and is not the live private configuration.

Run the supervisor with an absolute Python path and --config pointing to that private file. Keep Production gated off until the Sandbox child is healthy. Create the private Production gate only after its queue state and SMTP configuration pass review. Verify current supervisor and both database worker heartbeats before enabling the Production web queue and reloading the dispatcher. The current deployment was activated without creating acceptance-test messages; SMTP authentication does not prove inbox receipt.

Before a database restore, stop deliveries and preserve the independent attempts.db ledgers. Reconcile newer content and public-ID mappings before restoring. Run each affected environment's reviewed --invalidate-restored procedure under its exclusive worker lock before delivery resumes; it invalidates restored account tokens and queued intents. Never overwrite the replay ledger with an older application backup. This operation intentionally affects outstanding recovery links and needs a reviewed restore plan.

Rollback is reversible: disable the Production web queue and reload, remove its gate, and restore the recorded Sandbox-only task command if necessary. Preserve both replay ledgers, keys and accepted-send evidence; do not automatically restore a database after new activity. Production permanent retention is separately disabled and was not activated by this worker change.

Run `python ops/tests/verify_mail_supervisor.py` for 13 process, gate, restart, shutdown and shared-health checks. The authenticator replacement tests in each package use disposable databases and synthetic accounts; they never replace real factors or send mail. Full Production sign-off still requires approved real inbox tests, owner authenticator recovery/staff workflows, rights/guardian evidence and the retention decision.
