# Timeline, comment and search growth

Timeline pages fetch 21 visible post IDs to determine whether an Older link is needed. Only the selected 20 posts receive author and Vibe metadata. Single-post pages no longer count the entire site. Circle pins are read separately, respect search and visibility, and occupy one position in the same stable created_at/id ordering. Existing numeric page URLs remain supported; very deep pages still incur OFFSET work. Page controls display the current page without an expensive exact total.

Feed/profile previews show the latest five visible comments per post in chronological order. View all comments opens a post with windows of 50, with Earlier/More navigation. Windows use created_at/id boundaries, enforce moderation, member and age visibility before LIMIT, and never accept a target from another post. A comment query parameter opens a specific visible comment; old notification hash links recover that target in the browser. New comments preserve Feed/profile location; single-post submissions open the new comment. Reply indentation stops increasing after four levels.

External-content FTS5 trigram indexes cover post content, usernames, locations, and Circle names/descriptions. Automatic INSERT/UPDATE/DELETE triggers keep these indexes synchronized. Installation is transactional and backfills only newly created indexes. Searches retain escaped LIKE as the final literal substring check, existing privacy checks, and 20-result pages. Two-character terms retain the original scan. Terms matching over 200 indexed documents use the original ordered query after a bounded 201-row probe, avoiding a costly full-match sort. The search index never grants visibility or stores a second copy of source text.

Additional ordered post and comment indexes are additive; no journal-mode change or legacy table rebuild is required. Rollback is source-only: do not restore an old database over newer user activity. Additive indexes can remain when old source is restored.

Validation: run tests/verify_growth_queries.py and tests/verify_search_index.py with the staged package directory as their sole argument. Full-app privacy, profile pagination, navigation, statistics, Circles and sharing regression suites should also pass. Synthetic data belongs exclusively in Sandbox, with disabled sign-ins, example.invalid emails and an explicit record manifest. It is not a concurrent-user capacity test.
